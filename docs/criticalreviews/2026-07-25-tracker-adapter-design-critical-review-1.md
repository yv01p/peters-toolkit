## 2. Literal-wrongness findings

**F1 — §7 test spec asserts mapping of `state` and `url`, two fields the `getTicket` output contract deliberately excludes.**

- **Description.** §7 (line 165) says the tests' "Assertions cover: **id/title/body/state/url mapping**, full comment-array passthrough, label flattening, and that severity/attachments/links are empty." But the `Ticket` output contract has no `state` and no `url` field, in three independent places:
  1. **§5 projection table** (lines 114–123) lists exactly `id, title, body, comments[], labels[], severity?, attachments[], links[]` — no `state`, no `url`.
  2. **§5 conformance claim** (line 112): the projection "conforms to [the umbrella `Ticket`] exactly, **adding no fields**." The umbrella `Ticket` shape (umbrella §5 line 123: `{ id, title, body, comments[], labels[], severity?, attachments[], links[] }`) has no `state`/`url`.
  3. **§5 `getTicket` command** (line 109): `gh issue view <id> --json number,title,body,comments,labels` — `state` and `url` are never even fetched, so the recorded fixture (`tests/fixtures/issue-view.json`, generated by this exact command per §7/§3) will not contain them.
- **Why it's literal-wrongness.** `getTicket`'s asked-for behavior is to emit a `Ticket` matching the umbrella contract exactly. Following the spec as written produces a broken deliverable on *either* resolution path:
  - Build to §7 (assert `state`/`url` are mapped) → the projection must emit `state`/`url` → the `Ticket` no longer conforms to the umbrella shape "adding no fields," i.e. it is literally not the contract object the whole adapter exists to produce; and those fields aren't in the fetched JSON, so they'd map to `undefined` anyway.
  - Build to §5 (no `state`/`url`) → the §7 assertions test fields that don't exist and fail against the fixture → the shipped test suite (a §10 deliverable) is broken.
- **Evidence.** Spec `docs/specs/2026-07-25-tracker-adapter-design.md:165` (assertion list) vs `:109` (fetched fields), `:112` ("adding no fields"), `:114–123` (projection table); umbrella `docs/specs/2026-07-25-bug-fixing-workflow-design.md:123` (`Ticket` shape).
- **Proposed fix.** Correct §7's assertion list to match the actual contract — replace "`id/title/body/state/url mapping`" with "`id/title/body mapping`" (the scalar fields the `Ticket` actually carries). The empties assertion already correctly names `severity/attachments/links`. No change to §5, the `gh` command, or the umbrella shape is warranted: nothing in either spec calls for `state`/`url` in the `Ticket`, and adding them would be scope the user didn't ask for. (If a *later* workflow stage is ever found to require the issue URL/state, that is a change to the umbrella `Ticket` contract first — out of scope for this fix.)
